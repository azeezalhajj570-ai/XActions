# x402 audit, 28 August 2026

Scope: every payment path in this repo. What publishes the terms, what decides a
call was paid for, what signs a payment, and what the tests actually cover.

**The live site is sound.** `xactions.app` runs the Cloudflare Pages Functions
deployment, which verifies with the facilitator before serving, settles only
after the work succeeds, and advertises only the two endpoints it can really
serve. A junk `X-PAYMENT: not-a-real-payment` against
`POST /api/ai/scrape/profile` was answered `402`, correctly, during this audit.

The problems were in the other three payment paths that ship in this repo and
are wired into deploy commands but are not currently live. The worst of them
would have made every priced endpoint free on the next `wrangler deploy`.

| # | Finding | Severity | Status |
|---|---------|----------|--------|
| 1 | The Cloudflare Worker treated any `X-PAYMENT` header as proof of payment | High | Fixed |
| 2 | The paying client signed any amount, to any address, with no ceiling | High | Fixed |
| 3 | A Solana-only operator advertised Base terms payable to `""` | High | Fixed |
| 4 | 101 AI endpoints unpriced, 66 prices with no endpoint | Medium | Open |
| 5 | `/api/ai/health` and `/api/ai/pricing` advertised 11 chains the server rejects | Medium | Fixed |
| 6 | The x402 test suite tested a mock defined inside the test file | Medium | Fixed |
| 7 | Dev fail-open is silent, and one failed init meant 503 until restart | Medium | Fixed |
| 8 | The EVM scheme was registered against Solana network ids | Low | Fixed |
| 9 | `api/serverless.js` answered "Payment accepted" when nothing was | Low | Fixed |

---

## The four payment paths

Knowing which is which is most of the audit, because they behave differently
and only one of them is live.

| Path | Entry | Verifies? | Live? |
|------|-------|-----------|-------|
| Pages Functions | `functions/api/ai/scrape/*`, `src/edge/x402.js` | Yes: `/verify` before the work, `/settle` after it succeeds | **Yes, this is xactions.app** |
| Cloudflare Worker | `worker/index.js` (`wrangler.toml` `main`) | No, before this audit | No, but `wrangler deploy` ships it |
| Node backend | `api/server.js` + `api/middleware/x402.js` (`@x402/express`) | Yes, via the SDK | Only if self-hosted |
| Vercel serverless | `api/serverless.js` | No, and executes nothing | No |

---

## 1. The Worker treated a header as payment (High, fixed)

`worker/index.js` opened its gate with:

```js
if (request.headers.get('x-payment')) return null;   // then proxy to API_ORIGIN
```

Nothing decoded that header, and nothing asked a facilitator about it. Any
caller sending `X-PAYMENT: x` was proxied to `API_ORIGIN` and served. The
comment above it said "same behavior as api/serverless.js", which was true and
was the problem: that file does not execute anything, so the shortcut was
harmless there and fatal here.

This was not live, but `wrangler.toml` names this file as `main`, so a single
`wrangler deploy` from a clean checkout would have published a free API.

**Fixed.** The gate now decodes the payload, matches the chain the client chose
against the terms this edge actually published, calls the facilitator's
`/verify`, and refuses on a rejection with the facilitator's own reason. A
facilitator that cannot be reached is a refusal too: failing open on a payment
gate turns a thirty-second outage into free service. Settlement stays with the
origin, which owns the work and must not charge for a response it failed to
produce.

## 2. The paying client signed whatever it was asked for (High, fixed)

`src/mcp/x402-client.js` read `maxAmountRequired`, `payTo`, and `asset` out of
the 402 response and signed. There was no per-call ceiling, no session budget,
no payee allowlist, and no confirmation. The only limit was the wallet's USDC
balance and whatever allowance it had approved.

The server chooses that amount. One hostile or compromised endpoint, or one
typo in an endpoint URL, could have drained the wallet an agent was configured
with.

**Fixed.** `createX402Client` now enforces three limits before signing:

| Control | Default | Env var |
|---------|---------|---------|
| Per-call ceiling | $1.00 | `X402_MAX_PRICE_USD` |
| Session budget | $10.00 | `X402_MAX_TOTAL_USD` |
| Payee allowlist | off | `X402_ALLOWED_PAYEES` |

A 402 whose amount cannot be parsed is refused rather than guessed at. Each
refusal throws with `code: 'PAYMENT_LIMIT_EXCEEDED'` or `'PAYEE_NOT_ALLOWED'`,
so a caller can tell a budget refusal from a network failure.

## 3. Solana-only configuration advertised an unpayable address (High, fixed)

`X402_PAY_TO_ADDRESS_SOLANA` is a first-class setting: `validateConfig()`
accepts it alone, `isX402Configured()` returns true for it, and the edge
deployment really does take Solana. But `api/middleware/x402.js` built every
route with `network: NETWORK, payTo: PAY_TO_ADDRESS`, the EVM values.

Reproduced with the EVM address unset:

```
isX402Configured: true
validateConfig errors: []
route advertised:  { network: "eip155:8453", payTo: "" }
```

Base terms, payable to the empty string, published by a server that passed its
own validation. Every payment against it fails, and the operator's Solana
address is never offered.

**Fixed.** The Express middleware refuses to initialize when it has no EVM
address, with a message naming the two ways out: set an EVM address, or serve
the paid endpoints from the edge deployment, which offers Solana. Serving paid
routes free was the alternative, and it is not one.

## 4. Prices and routes have drifted apart (Medium, open)

Comparing `AI_OPERATION_PRICES` against the routes actually registered under
`/api/ai/**`:

- **101 existing POST endpoints have no price**, so on the Node backend they are
  free while their siblings are charged: `/api/ai/articles/publish`,
  `/api/ai/bookmarks/export`, `/api/ai/ads/campaigns`, and 98 more.
- **66 priced operations have no route.** `analytics:sentiment`,
  `business:competitor`, `article:publish` and others are advertised by
  `/api/ai/pricing` and `/api/ai/health` but resolve to nothing.

No money is lost on the second group: `@x402/express` cancels settlement when
the handler answers 4xx, verified in `node_modules/@x402/express/dist/cjs/index.js`,
so an agent gets a 404 rather than a charge. It is a discovery lie, not theft.
The live edge deployment does not have this problem, because
`src/edge/paidResources.js` only lists endpoints that exist.

Reproduce:

```bash
node --input-type=module -e "$(cat <<'EOF'
import { readFileSync } from 'node:fs';
const cfg = await import('./api/config/x402-config.js');
const priced = new Set(Object.keys(cfg.AI_OPERATION_PRICES)
  .map(op => 'POST /api/ai/' + op.split(':').join('/')));
console.log(priced.size, 'priced route patterns');
EOF
)"
```

**Open, deliberately.** Closing it means deciding, endpoint by endpoint, which
of the 101 should be paid and which are genuinely free, and deleting 66 stale
price entries. That is a product decision about what the hosted API sells, not a
bug fix. One instance was closed in this pass: `writer:comment`, added earlier
today, is now priced like its siblings.

## 5. Advertising chains the server will not accept (Medium, fixed)

`/api/ai/health` and `/api/ai/pricing` listed all eleven EVM chains from
`getAcceptedNetworks()` plus Solana, while every route advertised exactly one:
`NETWORK`. An agent that read the pricing document, picked Polygon, and signed
would be rejected, with nothing in the response explaining why.

**Fixed.** Both endpoints now filter to the network the server will actually
accept.

## 6. The test suite tested itself (Medium, fixed)

`tests/x402.test.js` is 1045 lines that build an Express app with a mock
middleware defined in the same file, then assert on it. Its "with valid payment"
block sends `signature: '0xMockSignature'` and expects `200`: the suite encoded
the header-is-payment bypass as correct behaviour. `tests/x402-integration.test.js`
needs a server on `localhost:3001` and is skipped in every run. Neither real
gate had any coverage.

**Fixed.** `tests/x402-gate.test.js` exercises the real modules with the
facilitator stubbed at the fetch boundary: 14 tests covering the challenge, the
header-is-not-payment regression, facilitator rejection, facilitator
unreachable, an unoffered chain, the success path, the requirement that
verification uses the terms *we* published rather than the ones the client sent,
free endpoints staying free, all three spend limits, and the Solana-only
refusal. The old suite is left in place; it is a useful shape test for the 402
document even though it proves nothing about the gate.

## 7. Silent dev bypass, permanent init failure (Medium, fixed)

Two failure modes in `api/middleware/x402.js`:

- With x402 unconfigured and `NODE_ENV !== 'production'`, every paid route was
  served free. That is correct locally and a disaster in a container that simply
  forgot to set `NODE_ENV`, which is a common deployment mistake.
- `_initFailed` was set once and never cleared. The usual cause is a facilitator
  briefly unreachable at boot, and the consequence was `503` on every paid call
  until someone restarted the process.

**Fixed.** The bypass now sets an `X-Payment-Bypassed` response header on every
request it lets through, so the condition is visible in any client or proxy log
rather than only in a boot message. A failed initialization is retried after 60
seconds.

## 8. EVM scheme registered for Solana (Low, fixed)

`server.register(networkId, new ExactEvmScheme())` ran for every id in the
supported-network list, including the two Solana CAIP-2 ids, inside a
`try {} catch {}` that discarded the mismatch. It either threw and was swallowed
or succeeded and left a scheme that would mis-verify a Solana payload.
Registration is now restricted to `eip155:` ids, with a comment saying where
Solana is actually served.

## 9. "Payment accepted" when nothing was (Low, fixed)

`api/serverless.js` passed any `x-payment` header through and then answered
`503 { message: 'Payment accepted. Connect to the Railway API for execution.' }`.
Nothing was accepted, verified, or settled. An agent reading that would
reasonably record a spend that never happened. It now answers a plain
`AI_EXECUTION_UNAVAILABLE` that says nothing was charged.

## What is good, and worth keeping

The live edge implementation is the model the other paths should follow:

- **`src/edge/paidResources.js`** refuses to advertise an endpoint that does not
  exist. Its header comment ("discovery documents are promises to a machine") is
  exactly right, and finding 4 is what happens without that rule.
- **Verify, work, settle, in that order.** A caller is never charged for a
  response they did not get.
- **`src/edge/facilitator.js`** intersects the offered chains with the
  facilitator's own `/supported` list, so the server cannot advertise terms its
  facilitator cannot settle, and falls back to the configured set when
  `/supported` is unreachable rather than turning the API free.
- **The dual v1/v2 challenge**: a v1 body with `base`/`solana` names and the v2
  CAIP-2 document in the `PAYMENT-REQUIRED` header, so clients of either
  generation can pay.
- **`PAY_TO_ADDRESS` has no default.** Nothing silently routes funds to an
  address the operator does not own.

## Recommended next steps

1. **Decide the paid surface** (finding 4). Which of the 101 unpriced endpoints
   should be paid, and which 66 price entries should be deleted. Then add a
   check to `npm run docs:check` that fails when a price has no route, the same
   way the MCP tool count is checked today.
2. **Point `wrangler.toml` at the verifying implementation**, or delete
   `worker/index.js` in favour of the Pages Functions deployment. Two edge
   implementations of the same gate is how one of them rots.
3. **Give the Node middleware Solana**, via `@x402/svm`, or document plainly
   that Solana is edge-only. Right now the config, the validation, and the
   discovery documents all promise a chain that one of the servers cannot take.
4. **Retire or rewrite `tests/x402.test.js`** so the suite stops asserting on a
   fixture, and make `tests/x402-integration.test.js` run against an ephemeral
   server instead of being skipped.

Method: read the four gates and the config end to end, diffed
`AI_OPERATION_PRICES` against the Express route tables programmatically,
reproduced the Solana-only case by running the real config module with the EVM
address unset, checked the SDK's settle-on-error behaviour in `node_modules`,
and probed the live service twice (once unpaid, once with a junk payment
header). No payment was signed and no funds moved during this audit.
